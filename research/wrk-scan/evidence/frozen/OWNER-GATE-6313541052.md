## 2. Gate I 的唯一实现范围

**研究隔离**：以最新 `origin/main` 建独立 worktree，用户现有 checkout 保持不变；选择仓库现有惯例下的 research-only 独立 crate/目录，避免向播放器产品 crate 引入依赖或运行时路径。一个 PR，多个逻辑 commits，**OPEN 等待 Owner merge**。修改 git 跟踪文件前明确目录边界。

**可以实现：**
1. `Frozen WorkloadCore`：字节级输入、SplitMix64、冻结 wait/CPU blocks/content/metadata/contribution/fault/aggregate；参考算法与运行时内容原语分离；独立 REF 只供测试/Oracle 消费，**executor 不得调用 ref_result**。不能将固定等待偷换成调度同步。
2. `ObserverSink` 与 `RAW_EFFECT_LOG / OWNER_TERMINAL_ACK_LOG`：保持真实 effect 边界和 terminal authority；ON 全量 Oracle，OFF 保留冻结的三时间戳、结果摘要、B/P 与 exit/join receipt。**同一构建产物、同一业务与生命周期代码，仅 observer 配置不同**；不能为了 OFF 删掉工作、取消、Join 或错误车道。
3. **干净 H0**：std-only，P 个长期工作线程 + 真实 `Mutex/Condvar` 谓词等待 + 共享 FIFO，B 是“已受理未 terminal”的全局许可而非 queue capacity；Admission/Cut 同一线性化区；ACK 后释放 permit；panic/worker death 由真实 owner 或明示 drain owner 清偿；settlement/producer_done/shutdown/所有 P workers join 后才发布最终 quiescence receipt。**不得直接复制 G2 probe 的 polling/50ms 诊断轮询/Mutation 分支当作 H0**。
4. 研究级 Correctness Harness：对冻结 O1–O10、K0 ON/OFF 控制线程所有权、逐项取消/清偿/exit、B/P 高水位和 Instrument ON/OFF 等价开展实际测试。K0 若无法在原 `!Send/!Sync` 语义下组合，先记录正交组合的不可比条件并求 Owner 裁决；不可修改 K0 使其迁移线程。

**不允许实现：** H1/H2a/H2b/H3/H4 候选、跨机制排名、正式 H×K0 全矩阵 Benchmark 框架、产品播放链改造、泛型 Scheduler/Actor Runtime、Native I/O 新层、Loom 扩张、冻结协议的非版本化修订。

## 3. Gate I 必须提供的可执行真实性证据

A. **源码权威**：freeze suite canonical digests 和 suite SHA 匹配；分离冻结规范、APP 研究 probe 与新 H0。WorkloadCore/REF 使用字节级黄金向量/独立参考对照；任何 `ARCHIVE_NORMALIZATION` 的 item_id 映射和 arm 排序不得擅改。

B. **实际的 H0 正确性**：真实 H0 worker 执行，非模拟 harness 自己把全部 item 记为已完成；首次运行先做小而有界的 fixture，随后在合理资源预算下运行各冻结 S×P×B **46 cells × K0 OFF/ON = 92 个非计时 correctness cases（至少一组固定、公开 seed）**。若个别 K0 组合确实 `NOT_APPLICABLE`，说明真实原因、保留单元槽位、不得无故抹去。观测 `B<=bound`、`active_item_execution<=P`、ACK owner、Cancelled group cut、Join 前不可发 receipt；对 S5 合法 Completed/Abandoned 混合，不强迫跨线程完成顺序完全一致。

C. **H0 自身的负控制**：在真正 H0 路径里以 test-only mutation 或独立替代补丁证明对应 O1–O10 的关键错误能被杀死，最低应覆盖 M1–M9 的性质家族（对于机制不可触发的特定注入形状给同义负控制）；每条保留 `GREEN → MUTANT RED → RESTORE GREEN`、mutant 源/命令/失败签名和非空跑。**G2 reference probe 的 9/9 不能替代 H0 mutation receipt**。不要把 mutant code 编入常规生产/正式性能构建，不加每次 CI 执行的昂贵 Mutation Gate。

D. **ON/OFF**：同一 binary 执行相同 `BatchSpec`，比较无取消 arm 的 admitted set、逐项 result digest、聚合/终局与 Join 事实完全一致；在 S5 允许合法的调度导致 Completed/Abandoned 类别不同，但必须各自被权威 Oracle 接受，group cut/被受理集合按因果里程碑等价。OFF 不自证正确：以独立 untimed shadow audit 或明确的恢复 ON 检测验证业务没有被旁路。其**仪器开销数字/排序效度属于 Gate III**，本 Gate I 不作性能比较。

E. **生命周期负控制**：针对 H0 lost wakeup、producer_done、consumer crash/panic、Full-B backpressure、取消 cut、未 Join，附最小 execution DAG 和清理所有权；不以 sleep 或 watchdog 作为同步证据。失败路径必须真实关闭/唤醒并 Join；若需要独立 OS 进程隔离恶意 mutant，说明范围及最终 cleanup。

F. **CI 与审查**：检查实际仓库适用的 Rust fmt/clippy/unit test/docs gates；运行是 non-timed correctness，不记录候选吞吐排名。最终 HEAD 由 Concurrency/Oracle/Minimality 三路独立审查，P1/P2 闭合；新 PR 不合并。每项失败和 `TOOLING_FAIL` 如实报告，不能用一项局部绿色替代全仓通过。

**Gate I 的 92 个 correctness case 与有限 mutation arm 只证明语义有效性；它们不是正式 30-seed/18,216 timed 进程的子集，不能混入性能表。**

## 4. 暂不批准的事项与需要另议的实验条件

- E5 已有只读 host survey，结论 `CONDITIONALLY_CAPABLE`。schedutil、Turbo、后台桌面、SMT sibling 非隔离、wakeup tracepoint 缺失仍是 Gate III 的环境/计量准入；当前无需修改 governor、全局 perf/cgroup/IRQ，也无需远程启动 Pilot。
- #306 的 SESOI 数字（throughput +10%、p99 −15%、CPU/item −10%、等）、7 sentinel cells、12 pilot seeds、Holm family、`n>100` 停止阈值和环境门槛都是**合理待裁决候选**，**并未因 Gate I GO 而获得冻结或运行许可**。
- 46 cells × 12 configurations × 30 seeds = 16,560 正式进程，以及 1,656 warmup，仅是 #306 的成本推导。等候有效的 pilot calibration 后再另行授权正式运行预算。
- H1 作为优先考虑的下一机制合理，但 **Gate II 单独审查/批准**；H2/H3/H4 不授权。
