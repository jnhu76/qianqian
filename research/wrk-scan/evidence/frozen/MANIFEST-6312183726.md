## 2. 规范化与哈希定义

GitHub 在保存评论时会在正文末尾追加一个 `LF`，因此“本地文件 exact hash”与“GitHub body exact hash”会相差一个字节。为保证未来研究者可独立复算，本归档同时给出两种身份：

```text
CANON(x):
  x = UTF-8 bytes
  line endings = LF（本归档本地文件与 GitHub body 均为 LF）
  strip all trailing LF bytes only
  no other normalization (no Unicode NFC/NFD, no whitespace changes)

SPEC_CANON_SHA256       = SHA256(CANON(spec_body))
APP_A_CANON_SHA256      = SHA256(CANON(app_a_body))
APP_B_CANON_SHA256      = SHA256(CANON(app_b_body))
APP_C_CANON_SHA256      = SHA256(CANON(app_c_body))
SPEC_GITHUB_BODY_SHA256 = SHA256(exact body returned by GitHub REST API)

SUITE_PREIMAGE = UTF-8 bytes of:
  "MVCS-R2-0-v3-SUITE\n"
  "SPEC <SPEC_CANON_SHA256>\n"
  "APP-A <APP_A_CANON_SHA256>\n"
  "APP-B <APP_B_CANON_SHA256>\n"
  "APP-C <APP_C_CANON_SHA256>\n"
SUITE_SHA256 = SHA256(SUITE_PREIMAGE)
```
